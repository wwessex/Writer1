# Narratryx Architecture

## Training pipeline

1. **Continued pretraining data** from PG-19 and Gutenberg English.
2. **Instruction SFT data** from Neural-Story and related fiction instruction corpora.
3. **DPO pairs** built using style-contrast transforms from high-quality "chosen" responses.
4. **QLoRA SFT** on Qwen2.5-7B.
5. **DPO refinement** on pairwise prose preferences.
6. **Export** to SafeTensors (cloud), GGUF (offline), and MLC (web).

## DPO pair quality strategy

- `chosen` is sourced from curated instruction responses.
- `rejected` is generated by controlled literary-degradation transforms:
  - remove descriptive adjectives,
  - flatten sentence variety,
  - normalize expressive dialogue verbs to generic forms.
- Each pair is tagged with provenance metadata (`pair_source`).

## Story Bible + saliency architecture

- IndexedDB-backed object stores for cards, scene chunks, model chunks, and generation history.
- Typed card schemas for character/world entities with trigger keywords.
- Hybrid saliency ranking:
  - keyword score over trigger terms,
  - optional embedding cosine score for semantic recall,
  - weighted combined ranking for active cards/chunks.
- Context assembler enforces token budget slices for cards, recent prose, summary, and generation headroom.

## Deployment targets

- **Cloud (primary):** vLLM + OpenAI-compatible gateway (`runtime/cloud/api.py`).
- **Modal path:** `runtime/cloud/modal_app.py` for scale-to-zero GPU hosting.
- **Container path:** Dockerfile + compose config for self-hosted GPU deployment.
- **Browser:** runtime selector for WebLLM/Wllama/cloud plus model chunk caching service worker.

## Isolation boundary

Narratryx is intentionally self-contained under `llm/Narratryx` and does not alter app runtime boundaries.
